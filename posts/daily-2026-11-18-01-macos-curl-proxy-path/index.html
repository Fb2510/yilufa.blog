Mac 浏览器能访问，终端却超时？检查代理路径

一路發2026-11-18— 次阅读
网络教程

浏览器能打开网页，终端里的请求却超时，不一定是节点失效。翻墙网络排障首先要确认两个程序是否经过同一个代理入口。代理入口就是本机软件接收请求的地址和端口，浏览器成功不能替命令行证明路径正确。

先确认环境与入口

以 macOS Tahoe 26 为适用环境，按苹果指南打开“应用程序”内的“实用工具”，双击“终端”。其他系统版本须核对相应指南与本机工具功能。

curl 是用命令发送请求的工具。项目说明确认系统自带 curl；需要新版时可从该页进入 Homebrew 安装渠道，本次排查不要求升级。先运行 curl --version 记录版本；下文要求至少 7.53.0，以支持覆盖代理绕过环境变量。

保持现有代理客户端运行，在设置中查到实际的本地 HTTP 或混合端口。它不是机场远端节点端口，也不是订阅地址；只有 SOCKS 端口时，不能直接照搬下面的 HTTP 示例。

用一次请求核对路径

在终端输入以下命令，按回车执行。7890 是假设端口，必须替换；示例网址也应换成你要检查的小型 HTTPS 页面：

curl -q --proxy http://127.0.0.1:7890 --noproxy "" --max-time 20 https://example.com/

-q 必须放最前，用来跳过默认配置文件；--max-time 20 将此次传输限制为二十秒。--noproxy "" 清空此次请求的绕过名单，避免环境变量让请求跳过代理，见参数说明。这些参数不会修改系统代理设置。

随后用原命令访问同一网址，保持节点和时间接近，记录两次结果；同时在客户端连接记录中核对是否出现这次请求。

目标是 HTTPS，本地入口仍可写 HTTP。官方说明解释，curl 会先通过代理建立隧道，再与目标进行加密通信，两个协议名称不能混为一谈。

成功以后查变量

若明确指定入口后恢复，检查原命令的代理来源。环境变量是程序启动时读取的配置值；curl 文档说明，HTTPS 目标可用 https_proxy，专用变量优先于 ALL_PROXY，NO_PROXY 可让指定域名绕过代理。HTTP 的 http_proxy 只接受小写。先核对这些值是否过期，再考虑持久化配置，不要公开含密码的变量。

若错误明确指向本机端口连接失败，先查客户端是否运行和端口是否匹配；若本地已接通，再结合客户端连接记录看请求命中的规则、出口与错误。收到网页内容，也可能只是错误页。

恢复连接后再评估套餐

固定节点地区和目标，分早晚重复请求，观察线路稳定性与网络延迟；另用定量下载检查节点速度。超时次数不能直接当作丢包率，丢包表现需用相同路径下的适当探测核实。

流媒体解锁要在播放器实际播放，海外 AI 服务可用性要完成一次真实任务，并核对官方支持地区。curl 连通不代表这两项通过。比较便宜机场套餐价格时，记录测试流量和节点计费倍率；本地入口配错通常不是增加流量额度能解决的问题。
